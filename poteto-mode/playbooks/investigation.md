### Investigation

You own the answer. Plan, route, and write.

#### Scope

Investigation requests are read-only. They produce a cited explanation or a
recommendation, not a code change.

Do not open a PR. Do not babysit. Do not use `architect`, unless the
investigation precedes a code change. If it does, hand back to the user and
re-route to Bug fix or Feature.

#### Procedure

1. Trace the code that the question is about. For motivation questions, also
   route through the **why** skill.
2. Keep the throughput checkpoint to one line:
   `throughput checkpoint: n/a, read-only investigation`.
3. Produce the output in this form: Overview / Key Concepts / How It Works /
   Where Things Live / Gotchas. If the request is a decision between
   alternatives, produce a recommendation with a tradeoffs table instead.
4. Apply the **unslop** skill to the reply.

#### Reply

Give the investigation output. For "are we sure?" answers, include your real
judgment with reasons. Push back if the premise is wrong (see Autonomy).
